# 02 · 功能划分

> 本文把产品诉求拆成可交付的功能单元：**F1–F9 功能域**、**P0–P7 页面**、**验收标准**、**优先级与依赖顺序**。
> 每条功能都标注了"谁实现"（对应模块），避免开发和产品理解错位。

---

## 1. 功能域总览

| 编号 | 功能域 | 一句话 | 主模块 | 优先级 |
|---|---|---|---|---|
| **F1** | 配置管理 | 导入、校验、多源并存、启用切换、导出 | `core:config` + `feature:settings` | **P0** |
| **F2** | 首页与栏目 | 按配置渲染栏目 Tab 与内容区块，分页加载 | `feature:home` + `render` | **P0** |
| **F3** | 分类与筛选 | 按配置渲染筛选条（分类/地区/年份/排序），结果墙 | `feature:home` + `render` | P1 |
| **F4** | 详情 | 元信息、简介、条目分组（线路/曲目/图集）、相关推荐、收藏 | `feature:main` | **P0** |
| **F5** | 搜索 | 单源/跨源聚合搜索，结果合并去重 | `core:source` + `feature:main` | P1 |
| **F6** | 播放与查看 | **视频 / 音频 / 图片三分支**：线路选集、后台音频、图片查看、进度记忆、直链解析、换源 | `core:player` + `core:ui` + `feature:main` | **P0** |
| **F7** | 历史与收藏 | 本地记录、续播、批量管理 | `feature:history` + `core:storage` | P1 |
| **F8** | 调试与诊断 | 配置体检（issues 带路径与原因）+ 导出脱敏；请求/响应/抽取可视化与配置沙箱**已删除** | `feature:settings` | **P0**（体验命门） |
| **F9** | 容错与缓存 | 阶段化降级、离线缓存、失败重试、换源提示 | 全局 | P1 |
| **F10** | 多端适配 | 断点布局、输入适配、播放器能力矩阵、打包产物 | `core:player` + `core:ui` + 各端入口 | P1 |

> **F8 为什么是 P0**：这个 App 的"内容"全部由用户手写 JSON 提供。
> 没有调试器，用户写错一个 `$.` 就只能看到白屏，产品直接死在第一关。
> 调试器不是锦上添花，是核心链路的一部分。

## 2. 逐项功能说明

### F1 配置管理

| 子功能 | 说明 | 验收 |
|---|---|---|
| F1.1 导入方式 | ① 粘贴 JSON 文本 ② 从本地文件选择 ③ 从 URL 拉取 ④ 扫码/分享 intent。**①②③已落地**（M5.1a）：设置页「粘贴」「导入」（Android SAF / 桌面 FileDialog）「URL」（Ktor 拉取，内网地址直连），双端实测通过；④未做 | 四种入口均可成功导入一份合法配置 |
| F1.2 即时校验 | 导入时执行 L1→L3 三级校验，错误精确定位到 `字段路径 + 原因` | 故意写错 3 处（缺 required、路径非法、引用不存在），三处全部被指出且路径准确 |
| F1.3 多源管理 | 同时保存 N 份配置，可命名、启用/停用、排序、删除；设置页列表**按状态分组**（已选择 > 待选 > 停用），组内保留手动顺序 | 同时存 5 份，切换启用后首页立即按新源渲染，无需重启；设置页里"使用中的那一个"始终排在第一组 |
| F1.4 源详情 | 展示配置的 `meta`（名称/作者/版本/说明）、资源数量、页面数量 | 与 JSON 内声明一致 |
| F1.5 导入导出 | 导出当前配置为 JSON（可复制/分享），支持"复制为模板" | 导出内容可回环导入并再次通过校验 |
| F1.6 版本迁移 | `schemaVersion` 落后时，按迁移链自动升级并提示 | 用 v0.9 样例配置导入，自动迁移到 v1.0 且功能不减 |
| F1.7 ~~预置数据源~~ | 🗑 **已废弃（2026-11-16，M5.10）**：APK / jar 都不再自带任何源，全部由用户导入（文件/粘贴/URL），源目录 Android `filesDir/sources`、桌面 `~/.vi-ump/sources`。全新安装时 `catalog.isEmpty()` → 直接进设置页提示先导入一份。历史上两端各有一份预置清单（`AssetSourceLoader` / `DevSourceLoader`） | 启动即看到用户导入的源；下拉可切换；坏配置只影响那一屏 |
| F1.8 样本即回归 | `samples/*.json` 既是文档示例也是回归样本：`SampleConfigTest` 会把目录下所有 JSON 编译一遍（任何一份编译失败即红灯）。所以"写一份能用得通的配置"这件事本身就是一次契约测试 | 新增一份配置后，`tools/validate_config.py` 与 `:core:config:jvmTest` 双双通过 |

> **新增回归样本：`samples/` 里的图集示例配置（整站 HTML）。** 4 个栏目（首页 / 受欢迎 / 画廊排行榜 / 标签排行榜）全部走
> `responseType=html` + `listSplit` + `regex`，实测 25 / 57 / 50 / 100 条、`skipped=0`（口径见 `docs/03 §5.4.2`）。
> 它同时暴露一处能力缺口：纯 HTML 源的分页图集（`#gdt` 雪碧图 + `/s/` 二段请求）当前 Schema 表达不了，
> 详情只到元信息 → `docs/04 §5.2.9`（候选方案 A：`episodes` 支持正则 id 表；B：`tracks.mode=html`）。

> **M5 导入/删除/排序/导出落地口径（2026-11，安卓模拟器实测）**
> F1.1 ✅ 三条通道全部落地：文件（Android SAF `OpenDocument` / 桌面 AWT `FileDialog`）、粘贴（对话框内校验）、URL（`fetchConfigText` 拉文本 + `LocalFirstProxySelector` 直连内网）。**分享 intent 明确不做**（用户已决）。
> F1.2 ✅ 导入即校验：`importEntryOf()` 走 `ConfigCompiler`，不过就把前两条 `[错误码] 路径 原因` 回显在"数据源"栏下方（粘贴/URL 通道把原因留在对话框里改完可重试），不允许静默失败。
> F1.3 ✅ 多源并存 + 切换 + 删除 + **启用/停用**：源落盘 `core:storage.UserSourceStore`（Android `filesDir/sources`、桌面 `~/.vi-ump/sources`），同 id 覆盖；**已无内置源**（M5.10），除当前源外都能删。**删除走左滑**（阈值 112dp，露出的「删除」再确认，取消回弹；2026-11-16 起去掉行尾删除按钮，也去掉 `↑`/`↓`）。停用（`SOURCE_DISABLED`）落盘、重启保持；停用的源从首页下拉消失、设置页仍在可再启用；全部停用时给兜底提示页。**源项单行化**（2026-11-15）：每一行 = 源名 + 状态（三态 `已选择 / 待选 / 停用`）+ 停用/启用 + （备份）+ 左滑删除，**列表按状态分组**（已选择 > 待选 > 停用，组内保持原顺序）；不再渲染 `SourceEntry.subtitle`；下拉菜单里用「源名 + `v<meta.version>`」单行区分源。**首页下拉限高**：按屏高算可见条数（一项 48dp、取屏高 55%、夹在 4~8 项），超出在菜单内滚动（见 docs/04 §7.4）。**备份**：每行「停用/启用」左侧有「备份」，写到一个用户选的持久目录（卸载不删，见 docs/04 §7.5.2）。
> F1.4 ✅ 设置页"当前数据源"区展示 meta / 站点 / 资源数 / 页面数；**「取数方式」一行已删**（全项目只有在线请求一种取法，这行回答的是实现方式而非源本身）。
> F1.5 ✅ 导出当前配置为**已脱敏** JSON（Android SAF `CreateDocument` / 桌面 `FileDialog(SAVE)`），导出文件可原样回环导入；"复制为模板/分享"暂不做。模拟器实测：示例源导出 15,783B 过 `validate_config.py`；带 `Authorization`/`X-Api-Key` 的 `mask-demo` 导出后 `author` 保留、三处凭据全部 `<已脱敏>`，该导出文件再走「导入」通道成功（同 id 覆盖）。
>
> 注：历史上曾记过"某类源不接入"的结论，后按用户要求推翻——它只以**开发期自测示例**的身份存在，
> 不进任何预置清单，也不影响 `samples/` 回归样本；仓库与发布包里都不带站点信息。

>
> **（历史记录）那份参考配置暴露的三个待办**——缺的都在 App 侧：
> ① `resources.search` 能写、`SourcePipeline.search()` 也在，但**没有搜索页入口** → **已接入**（M6.3，2026-11-16：顶栏 🔍 + `SearchRoute`，见 F2.11 / F5）；
> ② 选集缓存 TTL 固定 6 小时，而部分站的 m3u8 签名只活约 2 小时 → `docs/03 §5.5.4`、`docs/04 §7.10`；
> ③ 详情没有 `detail.playUrl`（首集地址要 POST 才知道），所以 F4.6 的「播放」按钮不出现
> → 建议按 `docs/04 §5.2.8 (2)` 补一级"有分组就从第一组第一条起播"的兜底；
> ④ 封面在 CDN 上是 **AES-128-CBC 密文**（换域名、换转码格式、加鉴权头都是密文），`poster` 字段本身没错，
> 缺的是图片通路的解码（`runtime.imageDecrypt`，F6.18 / `docs/03 §3.2`）——**已落地**（2026-11-16，客户端解密后正常出图）。

### F2 首页与栏目

| 子功能 | 说明 | 验收 |
|---|---|---|
| F2.1 栏目 Tab | 由配置 `pages[].channels[]` 决定（数量/名称/顺序全由配置控制）；每个栏目是一个取数入口（`feed` + `params`），布局沿用页面级。`children[]` 仍是"切布局"的老路子，与 `channels` 互斥 | 改配置的 channels 名称与顺序，重启后 UI 一致；切栏目数据随之更换 |
| F2.2 区块渲染 | 每个区块按 `layout` 类型渲染（`banner_hero` / `row_cards` / `poster_grid`） | 一个页面内混合 3 种布局正确渲染 |
| F2.3 分页加载 | 触底自动加载下一页，`paging` 规则由配置决定（参数名、起始页、hasMore 表达式） | 三种分页风格（page/skip/cursor）各验证一次 |
| F2.4 下拉刷新 | 刷新当前页，命中缓存策略 | — |
| F2.5 卡片模板 | 图/标题/角标/评分/年份的取值字段由 `card` 模板指定 | 改 `card.title` 指向别的字段，卡片标题随之变化 |
| F2.6 空/错状态 | 配置写错或接口挂了时给出可读错误 + "去调试"入口 | 断网时显示错误页而非白屏 |
| F2.7 数据源下拉 | 首页顶栏右侧显示"当前数据源"，点开列出全部**启用**的源：每项**单行**「源名 + 行末 `v<meta.version>`」，按屏高夹 4~8 项、超出滚动；**选中项不画 ✓，用它自己的标识色**（`meta.color` → 显式 `theme.primary` → 自动分配），其它项灰；选中即切换 | 切换后列表内容随之变化，顶栏文案与主色同步；没写 `meta.version` 的源不显示版本号 |
| F2.8 设置入口 | 顶栏最右齿轮 → 设置页：源列表（点击切换，按状态分组 已选择 / 待选 / 停用；**`↑`/`↓` 已删，组内只保留导入顺序**）、当前源信息、配置体检（issues 逐条 `[E00x] path message`）。源名颜色与下拉同口径：**已选择 = 该源标识色，待选/停用 = 灰** | 齿轮可点进去，返回后仍停在原数据源 |
| F2.9 视图切换 | 栏目条右端「▦ 网格 / ☰ 列表」按 `viewModes` 顺序循环，只换 `LayoutSpec.type`，不重新取数 | 切视图立即重排、不出现 loading |
| F2.10 会话级缓存 | 栏目数据缓存在 `UmpSession` 内，键为 `feed\|params`；切源即重建 session 丢弃缓存，进程退出失效；不落盘、不做过期淘汰 | 切栏目回来秒出；切数据源后同一栏目会重新请求 |
| **F2.11 搜索入口**（M6.3，2026-11-16） | 首页顶栏 🔍 在「源选择」下拉**左侧** → 进入**当前源内**的搜索页，结果只在该页展示；显示条件是 `flags.enableSearch && resources.search` 非空（两个都满足才出现）；切源自动关闭搜索页 | 配了搜索资源的源能看到 🔍 并搜出结果；只写开关不配资源的源看不到按钮 |

### F4 详情

| 子功能 | 说明 | 验收 |
|---|---|---|
| F4.0 列表可达内容页（2026-11-20） | **视频**点卡片直接进合并内容页：封面/播放键 + 标题/简介/演职员 + 选集；不再先详情再跳播放页。音频/图片仍走原详情入口 | 点视频卡片只出现一页；点播放或选集在同一页起播；返回直接回栏目 |

| F4.2 条目分组 | 视频=多组 chip（每组可切）+ 组内网格；音频=播放列表；图片=图集网格。**分组来源两条通路并列**：`detail.episodes`（逐条取数）与 `layout.tracks`（响应内切分） | 三份配置（video/audio/image）各正确分组 |

| F4.2.2 标签可区分性 | 同一期的"上/下/纯享/加更"必须显示成不同标签，不能全部塌成"第1集" | 同一期 4 条分别显示 `第1期·上纯享`/`第1期·下`/… |
| F4.2.1 选集与状态标 | 详情页把合集展开成格子：**正片一组并按集号排序，预告、花絮各自成组**；每格两行（集号 + 状态标 `免费`/`VIP`/`预告`/`花絮`）；点某格直接播该集，进度按集号分开存 | 示例配置里的剧集显示 选集 22 / 预告 20 / 花絮 5 三组；点第 1 集进播放页且标题为 `剧名_01`；选集有持久化缓存，二次进入 3 秒内出全集 |
| F4.3 相关推荐 | 详情接口返回的相关 ID → 二次请求列表接口 → `row_cards` | 有数据时正确渲染，无数据时不占位 |
| F4.4 收藏/取消 | 本地库写入，按钮状态即时同步 | 收藏后杀进程重进仍在 |
| F4.5 直达播放 | 有"上次看到第 N 集"则主按钮变成"继续观看" | 与 F7 联动 |
| F4.6 播放入口 | 内容页有播放地址时给出「播放」键，无地址时**不出现按钮**（不给点不动的按钮）。判定顺序是**详情优先、列表兜底**：列表条目里只有专辑 id，直链要等详情解析完才有。**2026-11-20 起播放键在合并内容页的封面上** | 视频源内容页可见按钮，纯图文源不显示 |
| **F4.7 默认自动播放**（2026-11-20） | 默认**关**：进视频内容页先停在封面与选集，点播放/某一集才起播。设置「播放 → 默认自动播放」可开，落 `SettingsKeys.PLAYER_AUTO_PLAY`（`player.autoPlay`，`1` 开）。开了之后详情返回即从第一组第一条起播。TV 端没有设置页，视频/音频点开即播 | 新装进内容页不自动播；开设置后再进同一视频自动播；TV 点视频即进播放 |

>

### F9 容错与缓存

| 子功能 | 说明 |
|---|---|
| F9.1 阶段化降级 | 抽取失败 → 该字段走 `default`；整条 item 失败 → 跳过该条并计数；整页失败 → 错误态 + 重试 |
| F9.2 内存缓存 | 同一次浏览会话内，相同 `(resource, params)` 的响应 LRU 缓存 5 分钟 |
| F9.3 磁盘缓存 | HTTP 层 `Cache-Control` + 可选的响应体缓存（max 50MB） |

| F9.5 超时 | **已落地（2026-11）**：单次请求超时取 `runtime.timeoutMs`（默认 15s），**上限 30s**，越界一律夹住；`createHttpClient()` 装 `HttpTimeout` 把连接/读/整体三项都设 30s 兜底（见 docs/04 §5.5） |

### F10 多端适配

> 约束：**一份配置、一套 Compose UI 跑在多端**。新增一个端 = 补齐该端 `actual` + 打包配置，不改 `commonMain` 业务代码。
> **唯一例外：Android 4.4.2 TV**。Compose / Media3 / Coil 的 AAR 最低都是 minSdk 21，API 19 装不上，所以 TV 使用独立 `:app:tv`（原生 View + ExoPlayer2），只共享纯 Kotlin 的 core 数据层。

| 子功能 | 说明 | 验收 |
|---|---|---|
| F10.1 断点响应式 | Compact(<600dp) / Medium(600–840dp) / Expanded(>840dp) 三档。配置里的 `posterColumns` 是**手机基准值**，其余端按断点放大 | 同一份配置：手机 3 列、平板 4 列、1100dp 桌面窗口 5–7 列，无需改配置 |
| F10.2 输入适配 | 触摸（双击快进/上下滑调亮度音量）、鼠标（hover 高亮、滚轮滚动）、DPad（TV 焦点） | TV 上任意可点元素可聚焦，焦点移动符合视觉顺序，返回键不误退出 |
| F10.3 播放器能力矩阵 | Android HLS 原生、iOS AVPlayer、桌面 VLCJ、Web `<video>`；格式支持各不相同 | 不支持的格式给出明确提示，而不是黑屏或崩溃 |
| F10.4 能力降级 | CSS 抽取器在无 HTML 解析能力的端降级为"文本 + 正则"；播放不支持时先尝试走解析接口取 mp4 | 每条降级路径在调试器里可见（可定位是"配置错"还是"平台不支持"） |
| F10.5 打包产物 | 手机 APK/AAB、TV 4.4 独立 APK、MSI/DMG/DEB、IPA、静态站点 | 每端都有可安装或可直接运行的产物 |
| F10.6 平台红线 | `commonMain` 不出现任何平台 API；平台代码只在 `xxxMain` 的 `actual` 中 | 静态检查（CI grep）：`commonMain` 无 `android.*` / `java.*` 引用 |

> 详细矩阵、各端实现选型与打包命令见 **`docs/06-多端适配方案.md`**。

#### F10 的验收边界（明确不承诺的部分）

- **iOS / Web 不在首版交付范围**：iOS 需 macOS + Xcode 环境；Web 受目标接口 CORS 限制，需先评估。
- **HTML 解析在 iOS/Web 端能力受限**：这两端先用正则降级，配置校验时对 `kind=css` 给出"当前平台不支持"警告。
- **Android TV 4.4 单独发 APK**：`:app:tv`（`com.vi.ump.tv`，minSdk/targetSdk 19），UI 与播放器不复用手机版 Compose/Media3；TV 音频不做后台、不发通知。

```
   ↓

   ↓

```
