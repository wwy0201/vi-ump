# 06 · 多端适配与打包方案

> 约束：**一份配置、一套 UI 代码，跑在多端**。
> 落地节奏：Android 先行，其余端按能力矩阵逐步开启（不改变 Android 的代码结构）。

---

## 1. 目标端与优先级

| 端 | 形态 | 输入方式 | 产物 | 优先级 |
|---|---|---|---|---|
| **Android 手机 / 平板** | 首发主力 | 触摸 | APK / AAB | **P0（当前）** |
| **Android TV / 盒子（4.4.2 / API 19）** | 独立原生 View 壳，非 Compose 同包 | 遥控 DPad | `:app:tv` APK | **P1（可测试）** |
| Windows 桌面 | 大屏窗口 | 鼠标键盘 | MSI（jpackage） | P1 |
| macOS / Linux 桌面 | 大屏窗口 | 鼠标键盘 | DMG / DEB | P2 |
| iOS / iPadOS | 触屏 | 触摸 | IPA（需 macOS + Xcode） | P2 |
| Web（Wasm） | 浏览器 | 鼠标 / 触摸 | 静态站点 | P3（探索） |

**原则**：新增一个端 = 补齐该端的 `actual` 实现 + 打包配置，**不改 `commonMain` 的业务代码**。

---

## 2. 代码共享边界

### 2.1 三层划分

```
┌──────────────────────────────────────────────────────────┐
│ 纯共享层（100% commonMain，零平台代码）                     │
│  core:model  core:query  core:config  core:common         │
│  core:ui     render      feature:main（UI + 页面状态，未上 ViewModel）│
└──────────────────────────────────────────────────────────┘
                          ▼
┌──────────────────────────────────────────────────────────┐
│ 平台抽象层（expect 声明在 common，actual 落在各平台）        │
│  PlayerFacade   播放器                                     │
│  HtmlParser     HTML 解析                                  │
│  KeyValueStore  轻量键值存储                                │
│  DatabaseDriver SQL 驱动                                   │
│  FileGateway    文件选择 / 分享 / 导出                      │
│  PlatformInfo   平台标识 / 屏幕断点 / 输入类型               │
└──────────────────────────────────────────────────────────┘
                          ▼
┌──────────────────────────────────────────────────────────┐
│ 平台专属层（只在该端的 source set 里）                       │
│  Android: Service / 通知 / 权限 / SAF / Leanback        │
│  Android TV 4.4: 独立 app/tv，原生 View + ExoPlayer2       │
│  iOS:     Xcode 工程 / UIDocumentPicker / AVPlayer         │
│  Desktop: 窗口菜单 / FileDialog / jpackage 配置            │
│  Web:     浏览器存储 / <video>                             │
└──────────────────────────────────────────────────────────┘
```

### 2.2 硬约束

1. `commonMain` 里**不允许出现** `android.*` / `java.*` / `platform.*` 引用。
2. 任何平台 API 只能出现在对应 `xxxMain` 的 `actual` 中。
3. `expect` 声明尽量少（当前规划 6 个）——每多一个，移植成本线性增长。
4. 新增端时，先跑通 `core:query` / `core:config` 的 `jvmTest`（纯逻辑无平台依赖，最容易验证）。

## 3. 能力 × 平台矩阵

| 能力 | Android | Desktop (JVM) | iOS | Web (Wasm) |
|---|---|---|---|---|
| HTTP | Ktor + OkHttp engine | Ktor + OkHttp / CIO | Ktor + Darwin engine | Ktor + Js engine |
| JSON | kotlinx.serialization | 同 | 同 | 同 |
| HTML 解析 | Jsoup（`androidMain`） | Jsoup（`jvmMain`） | SwiftSoup（cinterop）或**正则降级** | 正则降级 |
| 播放器（视频） | Media3 ExoPlayer（手机，退后台暂停）；ExoPlayer2 2.19（TV 4.4） | vlcj（解封装/解码交给 VLC，格式最全） | AVPlayer | HTML `<video>` |
| 播放器（音频） | Media3 + `MediaSessionService`（手机后台播放，设置可关）；TV 无后台、退后台暂停 | vlcj（无后台，关窗即停） | AVPlayer + `AVAudioSession` | `<audio>`（切后台可能被暂停，已知限制） |
| 数据库 | SQLDelight + `AndroidSqliteDriver` | `JdbcSqliteDriver` | `NativeSqliteDriver` | `WebWorkerDriver`（IndexedDB） |
| 键值存储 | DataStore / SharedPreferences | `java.util.prefs` | `NSUserDefaults` | `localStorage` |
| 图片加载 | Coil 3 + OkHttp fetcher | 同 | Coil 3 + Ktor fetcher | Coil 3 + JS fetcher |
| 图片查看 | Compose 手势 + Coil（**全端一致**） | 同（滚轮缩放） | 同 | 同（注意浏览器手势冲突） |
| 文件导入 | SAF（`ACTION_OPEN_DOCUMENT`） | `java.awt.FileDialog` | `UIDocumentPicker` | `<input type=file>` |
| 分享导出 | `Intent.ACTION_SEND` | 剪贴板 / 保存对话框 | `UIActivityViewController` | 下载 Blob |
| 手势 | 触摸 + 双击 / 滑动 | 鼠标拖拽 / 滚轮 | 触摸 | 触摸 / 滚轮 |
| 焦点导航 | DPad（TV） | Tab / 方向键 | 无 | 无 |

> **HTML 解析是最大短板**：iOS/Web 没有成熟 KMP HTML 库。
> 对策：`HtmlParser` 抽象成接口，iOS/Web 端先实现"正则降级版"（能力受限但可用），
> 并在配置校验时对 `kind=css` 在该端给出警告"当前平台不支持 CSS 选择器"。

## 4. 打包流程

### 4.1 Android

```bash
./gradlew :app:android:assembleRelease      # APK
./gradlew :app:android:bundleRelease        # AAB（上架）
```

- 签名：`keystore.properties`（不入库）+ `signingConfigs` 从属性文件读取。
- 分架构：`splits.abi` 或 AAB 由商店分发。
- TV：**不共用手机 APK**。4.4.2（API 19）需要独立 `:app:tv`：原生 View、ExoPlayer2、OkHttp 3.12、Conscrypt、multidex；包名 `com.vi.ump.tv`，minSdk/targetSdk 19，ABI `armeabi-v7a` + `x86`。
  构建：`./gradlew :app:tv:assembleDebug`，产物 `app/tv/build/outputs/apk/debug/tv-debug.apk`。

### 4.2 Desktop（Windows / macOS / Linux）

```bash
./gradlew :app:desktop:run                       # 本地调试
./gradlew :app:desktop:packageMsi                # Windows 安装包（需 WiX Toolset）
./gradlew :app:desktop:packageDmg                # macOS
./gradlew :app:desktop:packageDeb                # Linux
```

- `compose.desktop.application.nativeDistributions` 中配置 `packageName` / `packageVersion` / `targetFormats`。
- 打包自带 JRE（jpackage），无需用户装 Java。
- 需要图标：`iconFile` 指向 `.ico`(Windows) / `.icns`(macOS) / `.png`(Linux)。

### 4.3 iOS

```bash
./gradlew :shared:linkDebugFrameworkIosSimulatorArm64   # 生成 framework
```
- 需 macOS + Xcode；`iosApp/iosApp.xcodeproj` 引用生成的 `ComposeApp.framework`；
- 签名与上架在 Xcode 内完成（Archive → IPA）。
- **Windows 开发机上不可构建 iOS**：`kotlin.native.ignoreDisabledTargets=true` 已开启，构建时自动跳过。

### 4.4 Web（Wasm）

```bash
./gradlew :app:web:wasmJsBrowserDistribution
```
- 产物是静态 js/wasm + html，放任意静态服务器；
- 注意：**跨域**需要目标接口支持 CORS，否则需要代理——这是 Web 端最常见的阻塞点，P3 再评估。

## 5. 构建目标启用策略

| 环境 | 启用 target | 说明 |
|---|---|---|
| Windows 开发机（当前） | `androidTarget` + `jvm` | iOS 自动跳过；能在本机跑单测与桌面预览 |
| macOS 开发机 | 上述 + `iosArm64` / `iosSimulatorArm64` | 可出 iOS framework |
| CI | 矩阵：windows→android、linux→desktop、macos→ios、linux→wasm | 每端独立 job，缓存 Gradle |

`gradle.properties` 已有：

```properties
kotlin.native.ignoreDisabledTargets=true
```

含义：在不能构建 Native 的机器上，相关 target 被静默跳过而不是构建失败 —— 这是 Windows 上开发 KMP 的必要配置。

## 6. UI 响应式适配

### 6.1 断点

| 断点 | 宽度 | 典型设备 | 海报列数（默认） |
|---|---|---|---|
| `Compact` | < 600dp | 手机竖屏 | 3 |
| `Medium` | 600–840dp | 平板竖屏 / 折叠展开 | 4 |
| `Expanded` | > 840dp | 平板横屏 / 桌面 / TV | 5–7 |

实现方式：`BoxWithConstraints` 取 `maxWidth` 判定断点，不依赖平台 API。

### 6.2 布局参数覆盖链

```
配置 theme.posterColumns（基准，按 Compact 设计）
      ↓ 被断点系数放大
布局级 layout.columns（若显式声明，优先级最高）
```

规则：**配置的列数是"手机基准值"**，桌面端按断点放大，避免配置作者为每端写一套。

### 6.3 输入适配

| 输入 | 处理 |
|---|---|
| 触摸 | 双击左右区域快进/快退，上滑调音量、下滑调亮度 |
| 鼠标 | hover 高亮 + 点击；滚轮滚动列表；右键菜单（可选） |
| DPad（TV） | 焦点态必须可见（2dp 高亮边框 + 缩放 1.05）；`focusRequester` 保证首屏有焦点 |

TV 端三条硬要求：**任何可点元素必须可聚焦**、**焦点移动路径符合视觉顺序**、**返回键不误退出**。

## 7. 播放器抽象（跨端最关键的一处）

### 7.1 接口形态

```kotlin
// commonMain
expect class PlayerFacade {
    val state: StateFlow<PlayerState>
    fun prepare(url: String, headers: Map<String, String>, startMs: Long = 0)
    fun play()
    fun pause()
    fun seekTo(positionMs: Long)
    fun setSpeed(speed: Float)
    val supportedSpeeds: List<Float>
    fun release()
}
```

### 7.2 各端实现要点

| 端 | 实现 | 注意 |
|---|---|---|
| Android | Media3 `ExoPlayer` + `DefaultHttpDataSource` 注入 headers | HLS 原生支持；硬解失败降级软解 |
| Desktop | **vlcj 4.8.2 + 本机 libvlc**（已落地，见 `docs/04 §8.3.1`）；JavaFX Media 备选未采用 | 运行期依赖本机 VLC（找不到降级提示、不黑屏）；视频面是 heavyweight `Canvas`，控制条须放画面下方 |
| iOS | `AVPlayer` + `AVURLAsset` 的 `HTTPHeaderFields` | HLS 原生；不支持 mkv |
| Web | `<video>` + fetch/XHR 预取 m3u8 | 受 CORS 限制，需目标站点允许 |

**共同点**：`headers` 必须能注入（Referer 校验是各端都会遇到的）。

### 7.3 能力降级策略

配置里可声明播放格式偏好；某端不支持时：

```
平台不支持该格式
  → 尝试"解析接口"取 mp4 直链
  → 仍失败 → 提示"当前平台不支持，请在 Android/桌面端播放"
```

不静默失败、不假装播放。

## 8. 移植成本评估

| 模块 | 新增一端的工作量 | 说明 |
|---|---|---|
| `core:model` / `core:query` / `core:config` | **0** | 纯 Kotlin，直接编译 |
| `core:common` | 低 | 日志/调度器若用到平台 API 需补 actual |
| `core:ui` / `render` / `feature:main` | **0** | Compose Multiplatform 已覆盖 |
| `core:source` | 低 | 换 Ktor engine 即可 |
| `core:storage` | 中 | 换 SQLDelight driver + KV 实现 |
| `core:player` | **高** | 每端一个原生播放器封装 |
| 打包配置 | 中 | 每端 jpackage / Xcode / 静态站点 |

**结论**：UI 与业务逻辑的跨端成本几乎为零，成本集中在**播放器**与**打包**两处。
这也是为什么结构上必须尽早把 `PlayerFacade` 抽成 `expect` —— 越晚抽，改动面越大。

## 9. 落地节奏

| 阶段 | 端 | 动作 |
|---|---|---|
| M0–M4 | Android | 骨架、抽取引擎、渲染、详情、播放（全部在 androidMain 落地） |
| M5 | Android + Desktop | 开启 `:app:desktop`；抽出 `PlayerFacade` expect，Desktop 的 actual 先用"不支持"占位 |
| M6 | Android TV 4.4.2 | 独立 `:app:tv`：原生 View + ExoPlayer2 + OkHttp 3.12 + Conscrypt + multidex（**不能复用 Compose/Media3/Coil，三者 minSdk 都是 21**） |
| M7 | iOS | 需 macOS 环境；补 `htmlParser`/`storage`/`player` 的 iOS actual |
| M8 | Web | 评估 CORS 与 Wasm 兼容性后再决定 |

**关键**：M5 阶段就要把 `expect/actual` 的骨架搭起来（哪怕 Desktop 侧是占位实现），
否则等到真要上桌面时再拆，`core:player` 需要重构一遍。

## 11. Android 4.4.2 TV 独立壳（`:app:tv`）

### 11.1 为什么必须独立

实测 AAR 的最低 SDK：

| 依赖 | minSdk |
|---|---|
| Compose UI 1.9 / activity-compose 1.10 | 21 |
| Media3 1.8 | 21 |
| Coil 3.3 | 21 |
| core-ktx 1.16 | 21 |

4.4.2 = API 19。把 `minSdk` 强行改到 19 会在 manifest merger 阶段失败，所以 TV 不能复用手机版的 Compose UI、Media3 与 Coil，只能：
**共享纯 Kotlin 的 `core:model` / `core:query` / `core:config` / `core:source` / `core:storage`，UI 与播放器用 4.4 原生实现。**

### 11.2 模块配置

| 项 | 值 |
|---|---|
| 模块 / 包名 | `app/tv` / `com.vi.ump.tv` |
| minSdk / targetSdk / compileSdk | 19 / 19 / 36 |
| multidex | `multiDexEnabled = true` + `MultiDexApplication` |
| ABI | `armeabi-v7a`、`x86` |
| 网络 | OkHttp **3.12.13** + Okio **1.17.6**（4.x 下限是 API 21） |
| TLS | Conscrypt 2.5.2 + 内置 ISRG Root X1/X2、GTS Root R4 |
| 播放 | ExoPlayer2 **2.19.1**（core + hls + ui，minSdk 16） |
| 清单 | 无 Service、无 FOREGROUND_SERVICE、无 POST_NOTIFICATIONS |

`core:source` 默认依赖 Ktor/OkHttp4；TV 侧用 `exclude(group = "io.ktor")` + `exclude(group = "com.squareup.okhttp3")`，并在 `configurations.all` 强制回 3.12.13 / 1.17.6。

### 11.3 页面与输入

单 `Activity` + 页面对象栈（`TvScreen`），避免 4.4 盒子 Activity 转场慢、返回丢滚动位置。

| 页面 | 内容 |
|---|---|
| 源管理 | 源列表、`/sdcard/Download/*.json` 批量导入、设置/历史入口 |
| 首页 | 配置 `channels` 栏目 chips、海报网格、分页“加载更多” |
| 详情 | 元信息 + 分组/集列表；图片进查看器，视频/音频进播放器 |
| 图片查看器 | `←/→` 翻页、OK 显示/隐藏信息、懒取直链、向后预加载 |
| 播放器 | PlayerView + `<<` / `−10s` / 播放暂停 / `+10s` / `>>` / 返回 |
| 搜索 | 方向键软键盘（数字/字母/空格/删除/搜索）+ 搜索历史 |
| 设置 | 图片预加载 0–8、连续播放、清空本源搜索/观看历史、源管理 |
| 历史 | 当前源观看记录；OK 直接回上次那张图/那一集 |

焦点规则：所有可操作控件都是 `focusable`，页面进入后 `requestInitialFocus` 强制落焦点；4.4 部分盒子不把 OK 转成 `onItemClick`，列表/网格额外用 `setOnKeyListener` 在 `ACTION_UP` 兜底 `performClick`。

### 11.4 图片预加载语义（TV 与手机一致）

设置值 N = **当前张之后**预加载 N 张，只向后、不向前：

```
N = 3：看第 1 张  → 加载 1，预下载 2、3、4
       看第 15 张 → 加载 15，预下载 16、17、18
```

- 先解析直链（懒取图集走 `resolvePendingTrack`），直链一到就下载**字节**；
- 真正显示时才 `BitmapFactory` 下采样解码，字节缓存 12MB、Bitmap 缓存最大堆 1/8；
- 回看只靠已缓存直链/字节，不重新请求内页。

### 11.5 音频规则

TV 壳**没有**音频前台服务、没有通知渠道，也不申请通知权限：

- 视频/音频都只在前台播放；
- Activity `onPause` 调用当前页 `onPause` → `player.pause()` + 落进度；
- 回到前台保持暂停，由用户按播放键继续，不“后台偷偷播”。

手机版 `app:android` 的 Media3 后台音频 + 通知栏保持不变；其 `AudioPlaybackService.createChannel()` 已加 `Build.VERSION.SDK_INT >= O` 守卫，避免 API 24/25 触发通知渠道类缺失。

### 11.6 验收边界

- 仓库保证 `:app:tv:assembleDebug` 通过；`aapt2 dump badging` 为 minSdk 19 / targetSdk 19 / v7a+x86。
- **真机/盒子验收由用户执行**：4.4 的 Dalvik、TLS 根、遥控器 OK 映射、DocumentsUI 缺失等差异，只有真实盒子能确认；当前 Android 9 模拟器只验证 P0 安装/启动/网络。
